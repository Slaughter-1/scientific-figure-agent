# 研发过程与版本脉络

本文是公开研发摘要，不是原始会话、评审成绩单或运行日志。历史 FAIL 与验收限制不因 GitHub 发布而消失。实际提交身份以 Git 历史和发布记录为准。

## 1. 基础目标

项目希望把 LLM/NLP/Agent 论文中的方法描述转成可编辑结构图，并让使用者能够追溯“这个节点或关系来自哪一句话”“当前导出的到底是哪一个修订”。基础实现包含 Figure Spec、Draw.io 和 Matplotlib 后端、命令行、本地 Web/API 与文件任务存储。

默认自然语言入口实际调用规则式 parser/planner。LLM provider 是保留的扩展接口，不能将“支持 provider 类”描述成“默认依赖大模型规划”。实验数据图、静态模板目录、组件需求和资产引用作为并行模块保留。

## 2. 语义与证据

多轮定向修复集中在明确序列、条件分支、反馈、并行扇出/汇合、阶段包含与否定续作。规则能定位目标时保留原文证据；无法明确的关系进入 `needs_review`。

已处理的具体问题包括：把并列输入错画成数据流、把普通工具返回错当循环、遗漏明确反馈、返回后明确续作丢失、否定续作被误补为肯定边。修复作用范围由回归用例定义，不代表任意自然语言都能可靠解析。

## 3. 可编辑文件与 RoutePlan

早期存在预览与 Draw.io 节点尺寸、端点和标签位置不一致，以及正向与反馈边共线的问题。后续统一节点几何、端口与折线路径，构建 RoutePlan，并接入预览、Draw.io 和本地 Figma Scene。

Draw.io 修复包括 y 坐标翻转后分组矩形的归一、边标签原生 relative/offset 几何，以及独立参考公式和负向回归。原生客户端 CLI 对固定代表执行了保存、导出、重新打开；其结论限于实际测过的版本和代表，不扩张成全部 GUI 操作保证。

## 4. 审阅、修订与正式导出

审阅由仅保存记录推进为真正修改候选 Spec、保存修订、重新渲染并切换当前指针。候选选择绑定 revision 和 Spec hash；修改后旧选择失效。渲染失败不切换半成品。

正式 ZIP 导出交叉核对输入、Contract、Spec、候选、选择记录、素材和 evidence manifest；写入后重新读取包校验。候选预览可以存在待审问题，但正式导出不允许绕过相应门禁。

## 5. 素材链

素材从上传、登记、引用推进到独立显式许可批准。测试涵盖合法正例、未知许可、缺失许可证据和批准后字节变化。资产入包或登记不等于图标已被视觉合成，也不证明所有外部素材都可合法使用。

## 6. 真实栏宽与密集图

原始评测页面曾对同图作显示缩放，后来将 `paper_width` 贯穿 CLI、workflow、benchmark 和 API：结构图按 85/180 mm 分别生成，PNG 对应 220 dpi 约736/1559 px。

窄栏优化经历了异常长图、过度压缩造成文字挤出、分组标题越界等定向修复，最终使用有限三列布局和实际字体换行度量解决指定问题。其他复杂布局仍有真实待审项，不能把尺寸通过当成视觉质量通过。

## 7. 评测与协议教训

旧 R2 的样本在多轮修复中已经成为开发/回归材料。AI 评分必须与真实人工评分分开。S5-Agent-v1 改为隔离 Agent 材料构造、两路视觉评审和一次仲裁，但后续审计发现材料分类、版本声明、合并规则和视觉调用可追溯性问题。

最终保留原 R2/S5 FAIL，另记 S5 协议符合性 FAIL 与 qualified acceptance 未成立。没有改分、降门槛或重新标注为通过，也没有为了凑 PASS 无限生成新样本。

## 8. 工程收口

最终交付将应用与私有证据分离，补齐研发测试所需真实文件，并从最终 ZIP 的新解压目录完成安装、测试、API、业务导出、素材链和有限原生 CLI 检查。工程交付结束于 `DELIVERED_WITH_LIMITATIONS`，而不是科研图质量认证。
